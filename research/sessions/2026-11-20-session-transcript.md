**Orchestrator** runs your conversation in a **two-phase plan-and-execute workflow** using two different models instead of one:

1. **Planning phase (stronger model):** Every message you send starts here. For tasks that require changes or actions, the planner investigates read-only (reading files, searching, inspecting outputs), makes design and implementation decisions, and creates a concrete step-by-step plan.
2. **Execution phase (faster, lighter model):** Once the plan is ready, the planner hands off to a faster, lower-cost execution model within the same conversation to actually make the edits, run commands, and verify the results.
3. **Review & hand-back:** If the execution model runs into something unexpected, needs a decision, reaches a review point, or you send a follow-up message mid-task, control returns to the planning model to review progress and update the plan.
4. **Direct answers for questions:** When your request doesn't require edits or external actions (like asking a question or reviewing code), the planning model simply answers directly without handing off.

**In short:** It combines the reasoning strength of a flagship model for planning and hard decisions with the speed and efficiency of a lighter model for carrying out the work.
