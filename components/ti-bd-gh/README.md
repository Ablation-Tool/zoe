# TI‑style block diagrams that work in a GitHub README

A self‑contained replica of the interactive block‑diagram style used on TI's
"solution" pages (the one at `ti.com/solution/washer-dryer`), rebuilt so that it
survives GitHub's README renderer.

No JavaScript. No external dependencies. No build step for the consumer.
Everything lives inside the `SVG` file itself.

---

## The one thing you need to know first

GitHub renders README images as `<img src="...">`. That is a **sealed document**.
It has real consequences, and knowing them is 90% of "how do we copy that style".

| Capability | Inline / standalone SVG | **`<img>`‑embedded SVG (a README)** |
|---|---|---|
| JavaScript | runs | **never runs** |
| `:hover` / `:focus` / `:active` | works | **never fires** |
| `:has()` (highlight + dim siblings) | works | no — there is no hover to trigger it |
| CSS `@keyframes` | works | **works** |
| SMIL `<animate>` / `<animateTransform>` | works | works |
| CSS custom properties + `var()` | works | works |
| `@media (prefers-color-scheme: …)` | works | works |

So:

* **Hover interactivity cannot work in a README.** Not with CSS, not with JS,
  not with SMIL. The pointer never reaches the SVG document. This is a renderer
  constraint, not a limitation of our code.
* **Autonomous animation does work** in a README, because `@keyframes` are driven
  by the CSS animation clock, not by input events.

That is why this project ships **two variants**. Pick by where the file will live.

## The two variants

### 1. `block-diagram.svg` / `block-diagram-dark.svg` — hover variant

The authentic TI behaviour: hovering a block tints it with the accent colour and
**dims every sibling**, driven by `:has()`:

```css
.bd-nodes:has(.bd-subsystem:hover) .bd-subsystem        { opacity:.32 }
.bd-nodes:has(.bd-subsystem:hover) .bd-subsystem:hover  { opacity:1   }
```

Measured values, taken straight off the live TI page and reused here:

| Token | Value |
|---|---|
| accent | `#c8102e` |
| tint (hover fill) | `#fdf2f4` |
| sibling dim | `opacity: .32` |
| idle box fill / stroke | `#ffffff` / `#d6d6d6` |
| label / sublabel | `#262626` / `#8c8c8c` |

**Use it:** on a GitHub Pages page, in a local `index.html`, in any docs site, or
embedded inline in HTML. The flow lines still dash‑animate in every context.

**In a README:** it renders as a clean static diagram with animated flow lines —
the hover simply won't trigger. That is expected, not a bug.

### 2. `block-diagram-animated.svg` / `block-diagram-animated-dark.svg` — sweep variant

A scripted spotlight. A highlight sweeps the 13 blocks one at a time, dimming the
rest to `0.6`, forever. Pure `@keyframes` — **this is the one to use in a README.**

```css
@keyframes bd-dim      { 0%,4.23%{opacity:1} 8.85%,96%{opacity:.6} 100%{opacity:1} }
@keyframes bd-box-hi   { 0%,4.23%{fill:#fdf2f4;stroke:#c8102e;stroke-width:2.4} … }
@keyframes bd-label-hi { 0%,4.23%{fill:#c8102e} … }
```

13 blocks × 15.6 s / 13 = **1.2 s of spotlight per block**; the whole cycle is
15.6 s and loops seamlessly (each block enters and leaves at full opacity, so
there is no visible seam).

**Use it:** anywhere, including a README.

## Quick start (README)

Copy the SVG next to your README and reference it:

```markdown
![Washer and dryer system block diagram](docs/block-diagram-animated.svg)
```

### Add automatic dark mode

GitHub allows `<picture>` in Markdown, and a `<picture>` source is still an
`<img>` — so the sweep keeps animating and the user's OS theme picks the file:

```markdown
<picture>
  <source media="(prefers-color-scheme: dark)"
          srcset="docs/block-diagram-animated-dark.svg">
  <img alt="Washer and dryer system block diagram"
       src="docs/block-diagram-animated.svg">
</picture>
```

### Link out to the real thing

Ship the hover version too, and point people at a Pages URL for full
interactivity:

```markdown
[Interactive version →](https://<you>.github.io/<repo>/)
```

## GitHub Pages setup (for the interactive version)

1. Put `interactive/index.html` and the four SVGs in your repo, e.g.
   `docs/`.
2. **Settings → Pages → Source: Deploy from a branch**, branch `main`, folder
   `/docs`.
3. Visit `https://<you>.github.io/<repo>/`.

The Pages page uses the *hover* SVG inline in the document (not via `<img>`), so
`:has()`, hover, click‑to‑pin, the detail panel and the theme toggle all work.
A collapsed `<details>` fallback holds the plain `<img>` for the no‑JS case.

## Customising

Everything is generated by `make_diagram.py`; edit `subsystems.json` and rebuild.

```jsonc
{
  "id":    "sensors",
  "name":  "Sensors",
  "desc":  "Temp, humidity, level",
  "col":   2,        // grid column
  "row":   2,        // grid row
  "band":  "Sensing & Signal Chain"   // band header it belongs to
}
```

`col`/`row` of `-1` means "not in the grid" — that's how the System Controller is
placed as a full‑width footer block.

Then:

```bash
python3 make_diagram.py          # regenerates all four SVGs + interactive page
```

Common knobs, all near the top of `make_diagram.py`:

| Want to change | Change |
|---|---|
| Cycle length | the `15.6s` duration (must stay in sync with the keyframe `%` stops) |
| Dim strength | `opacity:.6` in `@keyframes bd-dim` (raise toward `1` for a subtler effect) |
| Palette | the accent/tint/idle constants |
| Geometry | `viewBox`, band heights, node size |

**Keep the keyframe percentages proportional.** The stops `4.2308%` / `8.8462%`
/ `96%` are `(1/13)·0.55`, `(1/13)·1.15`, `12/13+…` — they encode "hold, then
fade in, then fade out" per slot. If you change the block count, recompute them.

## Verification (what was actually tested)

Tested in Chrome 155 headless via the DevTools Protocol, against the exact files
in this archive.

**Hover variant, inline in a real page** — `cdp_page_test.mjs`:

```
before_hover  sensors  opacity 1  stroke rgb(214,214,214)  fill rgb(255,255,255)
after_hover   sensors  opacity 1  stroke rgb(200,16,46)   fill rgb(253,242,244)
after_hover   sibling  opacity 0.32
```

`rgb(200,16,46)` = `#c8102e`, `rgb(253,242,244)` = `#fdf2f4`. The hovered block
tints and the sibling dims to `0.32` — the measured TI values.

**Hover variant, inside `<img>`** — the control matters here. `cdp_anim_test.mjs`
hashes a region of interest across time with the pointer parked on the block:

```
inline:     flow_arrow_1.changed = true   block_fill.changed = false   ← hover works
img_embed:  flow_arrow_1.changed = true   block_fill.changed = false   ← hover dead, flow alive
```

In the `<img>` case `flow_arrow_*.changed` is `true` (the dash animation is
running) while `block_fill.changed` is `false` (hover genuinely does nothing).
Two different mechanisms, two different outcomes, measured in the same run — this
is the direct evidence for the table at the top.

**Sweep variant, inside `<img>`** — `cdp_sweep_test.mjs` samples each block over
time and counts distinct visual states:

```
block_00_input_protection  distinct=3
block_04_motor_driver      distinct=2
band_label_static          distinct=1   ← static control, correctly never changes
```

Blocks change. The static label does not. The animation is real and it is
running inside the sealed `<img>` context.

**Timing, not poked at through screenshots** — `cdp_anim_probe.mjs` asks the
document directly via `document.getAnimations()`:

```
42 animations   duration=15600ms   playbackRate 1.004× wall clock
```

42 = 13 blocks × 3 animated properties (`bd-dim`, `bd-box-hi`, `bd-label-hi`) + 3
flow lines.

## A bug worth knowing about if you edit this

**`animation-delay` is not inherited.** The first build put the stagger only on
the group:

```css
.bd-subsystem { animation-delay: var(--d) }   /* wrong — children still delay:0 */
```

The group faded in sequence, but every `.bd-box` and `.bd-label` lit up in
lockstep, because the delay never reached them. The fix is a custom property,
which *does* inherit:

```css
.bd-subsystem            { --d: 3600ms }
.bd-subsystem,
.bd-subsystem .bd-box,
.bd-subsystem .bd-label  { animation-delay: var(--d, 0s) }
```

If you add another animated child, add it to that selector list.

## Accessibility

* `role="img"` + `aria-label` on the root.
* `@media (prefers-reduced-motion: reduce)` disables the sweep **and** the flow
  dash animation, leaving a clean static diagram. This is honoured in the
  `<img>` context too.
* The Pages page marks the pinned block with `aria-current` and the blocks are
  real `<button>` elements.

## Browser support

| Feature | Minimum |
|---|---|
| `:has()` (hover variant only) | Chrome/Edge 105, Safari 15.4, Firefox 121 |
| CSS `@keyframes` (sweep variant, flow lines) | universal |
| `prefers-color-scheme` | universal in practice |

The sweep variant and the flow animation have no meaningful floor — anything that
renders SVG supports them. Only the hover variant needs `:has()`, and older
browsers degrade to a static diagram rather than breaking.
